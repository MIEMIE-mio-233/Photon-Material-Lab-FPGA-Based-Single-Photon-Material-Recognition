# 性能优化的来源与证据（2026-10-17）

来源：此前只看识别计算耗时，忽略读CSV、保存和网页绘图，容易把计算加速解释成整帧提速。分段计时后发现65536点CSV的格式化与解析占比较高，因此采集循环改存uint32 NPY，下载时才生成CSV；同时向量化绘图取峰点，并增量传递最近结果。

历史P4案例5次中位数：CSV写763.097ms、读3144.690ms；NPY写2.211ms、读2.690ms，计数与特征一致。测试保留OS缓存且未调用fsync，数值为该环境应用层时长。

电脑与P4使用1024个uint16灰度像素存储例，验证dtype和全部数值一致，统计warmup排除后的中位数/P95；另测fsync和单像素shape。不同输入哈希、模型、范围、负时间、阶段重叠和全warmup输入被拒绝。详见[validation-20261017.json](validation-20261017.json)。

100 kHz、100000次/帧的名义累积时间约1 s。历史10帧文件回放约0.204 s，单独记为回放速度。P4存储示例使用临时文件；重叠流水线另定义测量时间轴。

## 目录索引与显示延迟

板端每帧约1秒完成，但网页目录接口耗时数秒。检查发现采集进度触发全量目录请求，后台每次强制解析所有清单且持有索引锁。实现按清单修改时间和尺寸缓存批次、后台检查及状态快照，前端仅在需要浏览时刷新列表。

2920帧索引案例中，目录响应约1.1 MB，PC往返中位数由5423.014 ms（4次）降至193.915 ms（5次）。后续5帧不保存真实采集无识别异常，后4帧整帧处理中位数1025.483 ms。此处是HTTP与后台处理测量，屏幕更新另计。正式数值见[性能记录](../../../sim/results/capture_display_performance.json)，回归见[缓存检查](../../../src/ps/tests/test_catalog_cache.py)与[前端策略](../../../src/ps/tests/test_capture_refresh.js)。

方法适用于采集器、仪器控制及持续输出的监控网页。只有记录数变化并不能定位具体批次；缓存需要结合清单变更检测、文件删除及路径边界处理。清单未变化时手动删除单帧文件，可通过完整重新索引检查；本方法不保证在任意外部文件修改下即时同步。
